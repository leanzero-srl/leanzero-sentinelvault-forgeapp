1. Overview

Confluence records who changed a document. Sentinel Vault decides whether the change stands. It is an Atlassian Forge app for Confluence Cloud that lets you seal attachments and page sections, enforce approval workflows, check pages against content rules and classify every page from Public to Restricted. An edit that breaks a seal is undone automatically.

Everything runs inside Atlassian: the app declares no external hosts, stores its records in Forge storage, and its optional AI review uses Atlassian-hosted Claude through the Forge LLM API.

This guide describes production version 6.5.0. Several capabilities are off until an administrator turns them on: classification, signed actions, page comments that mention people, AI review, and attachment delete/restore/cleanup from the page.

2. Getting Started

  1. Install Sentinel Vault from the Atlassian Marketplace. A site admin opens Sentinel Vault — Site settings from Confluence's app administration and reviews the defaults.
  2. Open any page with attachments, choose ⋯ → Seal attachments… and pick the files to protect.
  3. Optionally insert the Sentinel Vault macro on the page for a panel that lists every file with its seal state.
  4. Space admins open the Sentinel Vault space page to see every seal in the space, set a space seal duration, configure the workflow and read the activity log.

4. Sealing Attachments

Seal a file and only you (and anyone you give edit access to) can change it until you release it or the seal expires. Seal from ⋯ → Seal attachments…, from the byline chip's page-details window, or with Seal in the inline panel.

  • Duration. A new seal lasts the site's Default Seal Duration (48 hours unless changed). A space admin can set a different duration for the space. Extend adds time to your own seal.
  • Release. Release ends the seal at once.
  • Expiry. With Seals expire on (the default) a seal runs out, the owner is reminded up to three times a day apart (as page comments, when those are switched on), and then the file is released. With it off, seals never expire and owners see a recurring banner instead.
  • Auto-insert. If a site admin turns on Auto-Insert Macro on Seal, the first seal on a page adds the panel to the page.

5. Sealing Page Sections

Open the page-details window from the byline chip and choose Seal a section…. Pick a heading: the seal covers the heading and everything under it up to the next heading of the same level. The section is wrapped in a Sentinel Vault Sealed Section macro and shows a badge with the owner and the end time.

If anyone other than the owner, or someone the owner approved, changes the section or removes it, Sentinel Vault puts the sealed content back from its snapshot. The rest of the page stays editable.

7. Edit Requests & Cooldown

On a file or section someone else has sealed, choose Request edit. The owner sees the request on the row, in the page banner and on My work, and answers Approve or Decline, optionally with a short reason.

The requester sees one set of states everywhere: Waiting for {owner}, Edit now · until {time} once approved, and Declined · ask again {time} when declined. Approved access ends with the seal.

Cooldown. After a decline the same person waits before asking again. The site setting Hours before a declined edit request can be repeated (editRequestCooldownHours) defaults to 1 hour, accepts 0 to 168, and 0 means no wait. The owner or a space admin can still give edit access directly at any time with Give edit access….

8. Force Release

A space admin can release someone else's seal with Force release…, which asks for a reason that is recorded. It is offered only while the site setting Allow space admins to force-unseal is on (it is on by default), so the menu never offers an action the server would refuse. The same switch also governs the other space-admin overrides: giving or revoking edit access on someone else's seal, releasing someone else's section, Approve anyway on a validation gate, a space's default level and direct workflow approvals.

9. Watching a Seal

Choose Watch for release on a file someone else has sealed. When the seal ends, Sentinel Vault posts a page comment that @mentions every watcher, and Confluence notifies them under their own notification preferences. This needs the site's Page comments that mention people switch, which is off by default.

10. Workflow & Approvals

Each space can run a page workflow. The built-in one is Draft → In Review → Approved, with Needs re-review when an approval lapses (after 150 days by default). A space admin configures approvers, how many must agree, the states and the moves between them in the space console's Workflow tab.

  • An Approved page is protected: an edit by someone who is not an approver or a space admin either moves the page back (demote) or is reverted, depending on the space's setting.
  • Approvers see what waits for them on My work and in the page banner.
  • The Workflow tab has a dashboard of page states with Export CSV.
  • A space can require a signed decision from approvers with an authenticator code (see Signing).

11. Validations & AI Review

Site admins define content rules in Site settings → Validations: required headings, tables and labels, heading hierarchy and length limits. Confluence publishes a page before an app can react, so rules apply after the save in three modes: advisory (a comment listing the issues, on by default), gate (a pass/fail state shown in the panel and banner) and revert (restore the last compliant version, opt-in). A space can switch a mode on, never off.

AI review is off by default. It uses Claude Haiku hosted by Atlassian through the Forge LLM API, with no API keys and no data leaving Atlassian, and can be capped with a monthly token budget.

12. Classification

Classification is off until a site admin turns it on with the switch in Site settings → Classification. Turning it off asks one confirmation and keeps every stored level, space default and page level.

LevelRankMeaning as shipped
Public1Safe to share outside the organisation.
Internal2For people inside the organisation only.
Confidential3Limited to a named audience; handle with care.
Restricted4Highest sensitivity; strictly need-to-know.
  • Your own levels. Rename, recolour, add or remove levels, or import them from a Jira Service Management Assets object type. The Assets calls run as the signed-in admin and nothing is written back to Assets.
  • Space defaults. Site admins set a default per space; space admins can set their own space's default from the space console while Allow space admins to force-unseal is on. A space can also opt out.
  • Per page. Anyone who can edit a page can set its level in the page-details window. The page's own level wins over the space default.
  • Visible everywhere. With classification on, every page shows its level under the title and in the banner, and says where it comes from: "set on this page" or "from space default". A page with neither shows "Unclassified".
Lowering asks for a reason. Raising a level is one pick. Lowering it, or clearing it, needs a reason of up to 300 characters, and the server refuses the change without one. Every change is recorded in the activity log with the old level, the new level and the reason.

13. Signing with an Authenticator

Sentinel Vault can ask for the current 6-digit code from an authenticator app before an action runs.

SettingWhereWhat it signs
Sign seal actions with an authenticator code (off by default)Site settingsSealing a file or section, releasing, force releasing and extending a seal, approving or declining edit requests, and giving or revoking edit access. Not signed in 6.5.0: a section sealed by inserting the Sealed Section macro and publishing, and REST API jobs.
Require a signed decisionSpace console → WorkflowEach approver's decision, a space admin's direct approval, and, with no named approvers, the space admin's direct approval (the requester signs only when an AI review step is involved).
  1. Each person sets up an authenticator app once on My work → Your approval signature: scan the QR code and confirm with the first code.
  2. A site admin turns on the site setting, and/or a space admin turns on signed approvals for the space.
  3. From then on the Sign this action dialog asks for the current code. Someone who has not set up an authenticator is refused until they do.

Each code works once. After 5 wrong codes, that person's signatures are refused for 15 minutes.

14. My Work

One page, every space: edit requests on your sealed files and sections, requests to become a space admin, your own edit requests and their states, approvals you asked for, the files you hold sealed, and your approval signature.

17. Notifications

Sentinel Vault sends no email itself. It tells people through pop-up messages, the page banner and, when the site turns them on, page comments that @mention the people involved; Confluence then notifies those people according to their own preferences. The comment master switch is off by default. A space admin can put one space in Quiet mode: no comments and no mentions there, while pop-ups, the banner and the activity log keep working.

18. REST API Tokens

Site admins mint named tokens in Site settings → API access. A token looks like svt_ followed by 48 hex characters and is shown once; only its SHA-256 hash is stored. Send it as Authorization: Bearer … or X-Api-Key.

RoleMay submit
ViewerNothing that writes (whoami only); for read-only integrations that may be widened later.
EditorContent operations: seal, unseal and extend files and sections, classify a page, workflow assign, withdraw and transitions, validation re-checks and approvals. Giving, revoking and declining edit access are content operations too.
AdminEverything above plus site and space configuration.

One endpoint, POST ?op=bundle, ?op=dry-run or ?op=whoami, with an Idempotency-Key header that becomes the job id. Bundles run asynchronously, site → spaces → content, with upsert semantics. Every operation runs as the admin who minted the token through the same checks as the UI, so a token can do nothing its minter cannot. The endpoint only ever answers with a fixed status and never returns data; results are written to Confluence properties you read with Confluence's own REST API.

19. Data, Licensing & Uninstall

  • Data residency. Seal records and settings live in Forge storage inside Atlassian Cloud; seal and classification markers are also written as Confluence content properties. The app declares no external hosts.
  • Licensing. Sentinel Vault is paid via Atlassian. If the app is unlicensed, sealed content stays protected and the admin consoles show a banner with Manage subscription.
  • Personal data. The app stores the Atlassian account ids and display names of the people who seal, request, approve and confirm, in its activity history, workflow history and read confirmations. It does not store email addresses. History older than Keep history for (Site settings → Privacy and retention, 730 days unless changed) is deleted by a weekly check.
  • Uninstall. Uninstalling does not delete everything. Atlassian keeps the app's Forge storage for its retention period after an uninstall. Two things stay in Confluence until you remove them: the backup page (titled Sentinel Vault backup, restricted to the app, holding a copy of your settings, seals, workflows and history), and the small markers the app writes on pages it protects (content properties such as protection- and sentinel-byline).
  • Removing the backup. Before you uninstall, go to Site settings → Backup and restore → Delete the backup. Every backup file is deleted for good and the emptied page goes to the space trash. If the app is already uninstalled, reinstall it, delete the backup this way, then uninstall again.

20. FAQ

My edit was undone. Is my work lost?

No. A file upload stays in the attachment's version history, and a page edit stays in the page history. The comment Sentinel Vault leaves you links to it.

I was declined. When can I ask again?

After the site's cooldown, 1 hour unless your admin changed it. The owner can also give you access directly at any time.

Why is there no Force release in my menu?

You need to be a space admin, and the site must have Allow space admins to force-unseal on.

I see no classification level.

Classification is off by default, or your space has opted out. A site admin turns it on in Site settings → Classification.

Nobody got a comment when a seal was released.

Page comments that mention people are off by default. A site admin turns them on in Site settings → Alerts, and a space in Quiet mode stays quiet.

Is my data stored outside Atlassian?

No.

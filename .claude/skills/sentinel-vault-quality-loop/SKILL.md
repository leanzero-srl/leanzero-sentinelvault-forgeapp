NOTE: the plain `realm.spec.ts`/`admin-render.spec.ts` render smokes are SHALLOW — they only assert "not blank", so a SPINNER passes them (that's why the it26 hang slipped through). The DEEP spec (`realm-console-deep.spec.ts`, added it26) is the real check: it enters the iframe with `readySelector: ".space-admin-title"` (a spinner can't match it → FAILS on a stuck-loading hang), then clicks EVERY tab and asserts each renders real content (no blank/error/spinner) + screenshots each. Extend it (or add a sibling deep spec) when a UI change needs a specific interaction verified live; a steward-console deep spec is a good next addition. The mock harness renders the *built* bundle with instant mock data; it CANNOT catch: (a) stuck-loading hangs (real resolvers that hang/slow — it26 found the realm-console hung forever awaiting `enumerate-operators`), (b) DEPLOY STALENESS (see below), (c) real-Confluence render/integration failures. If the render smoke only catches a transient loading state, add a longer-wait diagnostic spec (poll the iframe, or `page.waitForTimeout(22000)` + fullPage screenshot).

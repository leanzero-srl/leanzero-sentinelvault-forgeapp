# ADF-surgery / tamper-detection adversarial findings (it23)

3 adversarial reviewers (canonicalize/hash · media extract-splice · section-seal flow) audited `src/server/infra/doc-surgery.js` + the `triggers.js` enforcement flow. The core is well-hardened on the *visible-content-forgery* axis (SV-M7 pairs the 32-bit FNV hash with a full `JSON.stringify(canonicalizeAdf(...))` compare — collision-safe; A4 fixed media-nesting duplication). But the reviewers found a rich vein of real defects in the FLOW + edge cases. Triaged, most-severe first. **FIXED this tick: R2-F1.** The rest are the backlog for future core-touching ticks (verify-first + adversarial each before acting — a wrong fix here corrupts user content).

## FIXED
- **R3-F1 (HIGH, section-seal duplicate-sectionId desync) — DONE it24.** `restoreSealedSectionsPass` used a last-wins `Map` for detection while `replaceSectionBody` rewrote the first scan-match → a tamper on a non-selected copy was missed / the wrong copy restored (a false "reverted" notice while the tamper survived). Now groups ALL wrappers per sectionId (`wrappersById`), checks EVERY copy (`isUntouched`), and restores the sealed body into every differing copy by mutating the exact detected nodes (no first-vs-last desync). The implementation was adversarially reviewed (common single-wrapper case traces identically; live-node mutation persists; one notice per seal). It caught a NEW crash surface my refactor widened — `isUntouched` hashes every copy, so a malformed copy with missing `content` made `hashAdf(undefined)` throw + abort the pass — FIXED by making `hashAdf` nullish-safe (returns a sentinel `"00000000"` that won't match a real hash → fail-closed, the copy is restored). +3 unit tests; grade PASS (enforce 30/30); **deep E2E sealed-section 4/4**. NOTE R3-F2 (deep-nesting) is STILL OPEN — this fix uses the top-level-only `locateBodiedSectionNodes`, so a section MOVED into a container remains a blind spot.
- **R2-F1 (HIGH, media multi-version restore) — DONE it23.** `restoreMediaPass` (triggers.js ~369) broke the version-walk on the FIRST older version yielding ANY sealed media, so a second sealed file deleted in an EARLIER version was never restored (permanent bypass once past MAX_LOOKBACK). Fixed: accumulate across versions, shrinking a `stillNeeded` set (restore each file from the most-recent version that had it), stop when empty. +5 unit assertions; grade PASS (seal-revert 8/8, enforce 30/30).

## FIXED (cont.)
- **R3-F2 (HIGH, sealed section moved into a container) — DONE it25.** `locateBodiedSectionNodes` was top-level-only, so a section moved into a layout/expand/table cell read as "removed" → phantom top-level clone + nested tamper blind spot. Now scans DEEPLY; design decision = ALLOW the move + body-check IN PLACE (mutate the live node ref — no risky deep-remove). Impl adversarially reviewed: moved-section happy path CORRECT (found deep, body-checked in place, no clone), net improvement even for nested-sealed (previously cloned). +6 unit tests; deep E2E sealed-section 4/4. TWO residual EDGE findings recorded below (exotic, REST/nested-sealed-only — deferred, not fixed).

## BACKLOG (confirmed, unfixed — ranked)
1. **it25-review-F1 (MED, nested SEALED sections double-process).** With the deep scan now recursing INTO sealed bodies, a sealed section B inside another sealed section A yields BOTH. Since A's content contains B, tampering B flags both; seals iterate in KVS (not doc) order, so: process-A-first → B's node goes stale → B's in-place restore is a no-op BUT a second `section-revert` notice still fires (duplicate notices); process-B-first then A → A's (older) snapshot can OVERWRITE B's just-restored newer content (baseline loss) if nested baselines diverged. No crash/corruption (stale mutation is a no-op). Reachable only by sealing a range that includes an already-sealed wrapper, or REST. FIX: process nested sealed sections in document order + skip a section subsumed by an ancestor's restore (or forbid sealing a range containing a sealed wrapper at seal time).
2. **it25-review-F2 (LOW-MED, LOW confidence · schema-invalid restore into a nested position).** Restoring `snapshot.bodyContent` (captured at top level) into a wrapper now nested in a tableCell/layoutColumn could yield ADF illegal at that depth → the whole-page PUT 400s → NO seal on the page is restored + no notice (silent until a later edit). Hinges on whether ADF even permits a `bodiedExtension` in a tableCell/layoutColumn (if not, the move is rejected upstream = moot). VERIFY with a live test (seal a section with a table, move into a table cell, tamper, confirm the PUT) before fixing.
3. **R3-F2 old top item — SUPERSEDED (fixed above).** `locateBodiedSectionNodes` (doc-surgery.js ~664) scans TOP-LEVEL only. A sealed section dragged into a layout column / expand / table cell is read as REMOVED → a fresh top-level clone is spliced in → TWO sections: the nested live one (never scanned = permanent tamper blind spot) + the clone. Also a false `kind:"removed"` notice, and the removed-branch never checks `getActiveSectionEditGrant` (an approved editor who moves a section is blocked + falsely accused). FIX: make locate scan deeply (find the section wherever it is) and decide move-policy (revert the move vs allow + body-check). MED fix confidence (semantics change) — pairs with R3-F1.
3. **R1-F3 (MED-HIGH likelihood · macro `macroId` not volatile → spurious reverts).** `VOLATILE_ADF_KEYS` = {`localId`} only. Confluence regenerates `attrs.parameters.macroMetadata.macroId.value` (a GUID) on save; any Approved page / sealed section containing a macro (info/note/code/expand/panel — very common) that a non-owner re-saves as a no-op canonicalizes differently → destructive whole-body revert + false "tamper" notice + version churn. "Most likely to actually fire in production." FIX: add `macroId` (and see R1-F4: media `occurrenceKey`, maybe `width`/`height`) to the volatile strip. **BLOCKED: needs a live-editor round-trip to confirm which attrs the editor regenerates** (the code comment says "HARDEN EMPIRICALLY") — do it against the real dev site before shipping, else risk false-negatives. This is a false-POSITIVE (annoyance/churn), not a security hole.
4. **R2-F2 (MED · mediaGroup/bare-media restore lacks width/height).** When a sealed media had no `mediaSingle` ancestor (it was in a `mediaGroup`/attachment strip), extract wraps the bare media in `{mediaSingle, layout:center}` with NO `width`/`height`. Rendering changes, and Confluence's server-side ADF validation MAY reject the whole PUT → the entire restore write fails → tamper persists. Verify the live schema strictness; if strict, carry width/height (or restore as a mediaGroup).
5. **R3-F6 / R1-F1 (LOW-MED · unguarded throws abort the whole pass).** `hashAdf(undefined)` throws (str.length on undefined) — called unguarded at triggers.js ~460/523; and deep-nesting (thousands of levels) throws RangeError in canonicalize/JSON.stringify. Either aborts the per-page pass → all remaining seals on that page skipped that save (missed tamper on siblings), and the deep-nesting case never self-heals on the sweep either. FIX: guard `hashAdf`/canonicalize against nullish + a depth cap (fail CLOSED — treat as tampered, don't skip).
6. **R3-F3/F4/F5 (MED-LOW · degrade-unsafe on missing/partial KVS).** — **F5 empty-bodyContent PART: DONE it40.** The LIVE restore (triggers.js ~572, `w.node.content = snapshot.bodyContent`, gated only on the truthy `if (snapshot?.bodyContent)` — and `[]` is truthy) wrote `content:[]` for an empty-baseline section = invalid ADF → whole-page PUT 400s → EVERY sibling restore on the page dropped. FIXED: extracted `nonEmptySectionBody()` (one empty paragraph, mirrors buildSealedSectionNode) + applied at the build site AND the restore; +4 unit tests, grade PASS, deep sealed-section E2E 4/4 (common path unchanged). Also hardens non-array snapshots. **STILL OPEN (F3/F4):** missing `section-snapshot` → SV-M7 trusts a bare hash match (forgery surface reopens) + the body-edit branch does NO restore (tamper stands, only a log); missing `seal.contentHash` → restore-on-every-save churn, never self-heals. FIX: fail CLOSED on missing snapshot. (F5's empty-body LIVE E2E — seal an empty section, tamper, assert the PUT succeeds — not yet built; the fix is unit-proven + the common path is byte-identical.)
7. **R1-F2 (LOW · `__proto__` own-key dropped).** `out[k]=…` for `k==="__proto__"` hits the prototype setter, so a REST-supplied `__proto__` own-key vanishes from the canonical form → two different payloads canonicalize equal (covert channel; NOT visible-content forgery, and no global pollution). FIX: `Object.defineProperty(out, k, {value, enumerable:true, …})` or skip `__proto__`.
